# Trailer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 62 s, 1920×1080, 60 fps trailer filmed by the game itself, encoded to `builds/trailer/the-condo-trailer.mp4`
and uploaded privately to Drive.

**Architecture:** `tools/trailer.gd` is a SceneTree script, like `tools/stills.gd`. It loads `scenes/main.tscn` and
plays a timed shot list through the game's own state, signals and nodes. Godot's Movie Maker records it as PNG
frames plus a WAV. `tools/trailer.sh` trims off the loading frames, sets the loudness, encodes the MP4, measures
it and makes a contact sheet.

**Tech Stack:** Godot 4.7.2 (typed GDScript, Compatibility renderer), Movie Maker (`--write-movie`), ffmpeg
(libx264, aac, ebur128, alimiter, tile), rclone.

**Spec:** `docs/superpowers/specs/2026-11-05-trailer-design.md`

## Global Constraints

- Godot binary: `GODOT=/Users/chrischeng/tools/godot-4.7.2/Godot.app/Contents/MacOS/Godot`. Tests:
  `GODOT=$GODOT tools/test.sh [--filter=x]`.
- Tease only: nothing from the window becoming a door. No gap, no B-11-07, no `bedroom: door` variant, no act 3 or
  later, no endings.
- Filmed with the shipped defaults: filter on, field of view 72, head bob 100%. The two exceptions are the clock
  close-up at field of view 28 and the subtitle label drawn at font size 34 instead of 24.
- About 60 s, accepted at 55–65 s. 1920×1080, H.264 yuv420p, AAC 48 kHz, in an MP4.
- Loudness: about −18 LUFS integrated (−19 to −17), true peak at or under −1 dBTP. One fixed gain plus light
  limiting, at most 6 dB, on the hits only.
- Captions are the game's own text. Cards are drawn in Godot in the game's default UI font. No music, no
  voice-over, no post effects the game doesn't render.
- No gameplay code changes. The trailer reads and drives game nodes from `tools/` (private members too, as
  `tools/stills.gd` does). The owner's settings file is never written.
- Output goes to `builds/trailer/`, which git ignores. Nothing is pushed or merged. The Drive upload stays
  private, and no share link is made.
- The Mac is shared: stop only processes this work started.

## Review Focus

1. **The owner's saved settings leak in.** For example `user://settings.cfg` sets field of view 80, head bob 0,
   captions off or a lower volume. Expected: the trailer films with `Settings.DEFAULTS` and never writes the
   file. Pinned by `test_trailer_films_with_the_shipped_settings` (Task 1).
2. **Movie Maker records from engine start, before the trailer begins.** That includes the shader warm-up tour
   and the start card. Expected: these frames are covered black and trimmed, and the MP4's first frame is the
   black 11:47 card. Pinned by the black cover from the first frame (Task 1) and contact-sheet frame 0.5 s
   (Task 2).
3. **A figure is never "seen".** The game's sighting uses physics rays, so the figure may not register. Then
   the hallway figure never hides, and the kitchen figure plays no stinger. Expected: the run fails, not a
   silent wrong trailer. Pinned by the runner exiting 1 when a figure cue gets no `silhouette_seen` (Task 1),
   and by the sheet frames at 48.0 and 49.8 s (Task 2).
4. **A spoiler reaches a frame.** Expected: no shot's setup puts the player in `gap` or `mirror_room`, sets
   `bedroom` to `door` or an act above 2. Pinned by `test_no_trailer_shot_shows_past_the_window_door` (Task 1).
5. **The AAC encode pushes the true peak over −1 dBTP, or the limiter squashes more than lightly.** Expected:
   `trailer.sh` measures the final MP4, not the WAV, and fails above −1.0 dBTP or above 6 dB of limiting.
   Pinned in Task 2, Step 3.

### Task 1: The trailer script

**Files:**
- Create: `tools/trailer.gd`
- Test: `tests/integration/test_trailer.gd`

**Interfaces:**
- Produces, used by Task 2 and the tests:
  - `const SHOTS: Array[Dictionary]`. Keys: `name: String`, `at: float`, `len: float`, `act: int`,
    `pos: Vector3`, `yaw: float`, `pitch: float`, `lights_on: Array[StringName]`,
    `lights_off: Array[StringName]`, `variants: Dictionary`, `phone: bool`, `fov: float` (0 = default),
    `clock: bool`, `black: bool`, `walk: Vector2` (zero = none), `creep: float` (metres),
    `cues: Array[Array]`.
  - Each cue is `[time: float, kind: String, ...args]`. Kinds and args:
    - `"card", style: String, text: String, until: float`
    - `"say", text: String, seconds: float`
    - `"sound", id: StringName, pos: Vector3, db: float`
    - `"act", act: int`
    - `"stop_bed", id: StringName`
    - `"variant", area: StringName, variant: StringName`
    - `"turn", radians: float, seconds: float`
    - `"figure", anchor: StringName, seconds: float`
    - `"black"`
  - `static func prepare(main: Node3D) -> void`:
    - sets `Settings.values = Settings.DEFAULTS.duplicate()`, then calls `Settings._apply_volume()` and emits
      `Settings.changed`. It never calls `set_value`, which saves.
    - `player.input_enabled = false`, so main never steps the horror runtime or opens the pause menu.
    - hides `hud._start`, `_crosshair`, `_prompt`, `_clock`, and `_objective` (text "").
    - `hud._subtitle.add_theme_font_size_override("font_size", 34)`.
  - `static func set_up_shot(main: Node3D, shot: Dictionary) -> void`. It applies everything in the shot's
    "setup" column:
    - act, lights (each room's `ApartmentLayout.LIGHTS[room]["on"]`, plus `lights_on`, minus `lights_off`), variants, position and look, phone,
      field of view, HUD clock;
    - figure hidden, `scripted_move` zero, player physics on only for walk shots;
    - then `WorldState.set_player_room(...)` and `main.look.settle()`.
  - Command line:
    - `"$GODOT" --path . --resolution 1920x1080 [--write-movie <abs>/frame.png] --script res://tools/trailer.gd [-- --until=<seconds>]`
    - It prints `TRAILER_FRAMES <first> <count>`: `Engine.get_process_frames()` at the trailer's first frame,
      and the frame count. It quits 0, or 1 when a figure cue got no `EventBus.silhouette_seen` within 1.5 s.

- [ ] **Step 4: Implement `tools/trailer.gd`**

  Header comment in the style of `tools/stills.gd`: what it does, the command line, and that it needs a window.

  `_initialize()`:
  1. Add the trailer CanvasLayer with black on, before adding main, so the warm-up tour is never seen.
  2. Wait for `main.loaded`.
  3. `prepare(main)`.
  4. Print `TRAILER_FRAMES` (first part), then run the shots on a frame counter: `t = frames / 60.0`, one
     `await process_frame` per frame. Fire each cue once when `t >= at + cue time`.
     - Turns ease with `smoothstep` on `player.set_look`.
     - Creep moves `player.global_position` along the view direction, with player physics off, so there are no
       footsteps.
     - `"say"` emits `EventBus.subtitle_requested`, so the HUD shows it as in the game.
     - `"stop_bed"` sets `audio._stopped[id] = true`, then calls `audio._stop_bed(id)`.
     - `"figure"` emits `EventBus.silhouette_requested(anchor, seconds)`. Leave the figure's
       `_physics_process` on, so the game's own sighting, hiding and stinger run. Count `silhouette_seen` per
       figure cue.
  5. Stop at `--until` if given.
  6. Print the frame count, free main, and quit with 0 or 1 (see Interfaces).

  Fill `SHOTS` from the table above.

### Task 2: Record, encode, measure

**Files:**
- Create: `tools/trailer.sh`
- Modify: `docs/architecture.md`: one paragraph after the `tools/models.sh` one, naming `tools/trailer.gd`,
  `tools/trailer.sh` and `builds/trailer/`.

**Interfaces:**
- Consumes: Task 1's command line and its `TRAILER_FRAMES <first> <count>` line.
- Produces:
  - `builds/trailer/the-condo-trailer.mp4`;
  - `builds/trailer/sheet.png`;
  - `builds/trailer/report.txt`, holding the ffprobe line, input I/TP, gain, output I/TP and limiting dB;
  - `builds/trailer/render.log`.

- [ ] **Step 1: Write `tools/trailer.sh`** (bash, `set -euo pipefail`, `GODOT` from the environment like
  `tools/test.sh`, run from the repo root).

  1. Clear `builds/trailer/raw/`. Run the Task 1 command with
     `--write-movie "$PWD/builds/trailer/raw/frame.png"`, tee to `builds/trailer/render.log`, and fail on a
     non-zero exit.
  2. Parse `first` and `count`. Set `S = first / 60` and `LEN = count / 60`.
  3. Pass 1: `ffmpeg -ss S -t LEN -i raw/frame.wav -af ebur128=peak=true -f null -`. Parse the summary's
     integrated `I` and true `Peak`. Set `GAIN = -18 - I`.
  4. Encode:
     - inputs: `-framerate 60 -start_number first -i raw/frame%08d.png`, plus the WAV with `-ss S -t LEN`, and
       `-frames:v count`;
     - audio:
       `-af "volume=${GAIN}dB,alimiter=limit=0.75:attack=5:release=80:level=0,afade=t=in:d=0.5,afade=t=out:st=$(LEN-1.5):d=1.5,aresample=48000"`.
       Check the option names with `ffmpeg -h filter=alimiter`. If `latency` exists, add `latency=1`.
     - codecs: `-c:v libx264 -preset slow -crf 16 -tune grain -pix_fmt yuv420p -c:a aac -b:a 256k
       -movflags +faststart`.
  5. Measure the MP4:
     - `ffprobe` width, height, duration, and video and audio codecs;
     - `ebur128=peak=true` for output `I` and `TP`;
     - `LIMIT = (input TP + GAIN) − output TP`.
     - Write all of it to `report.txt`.
     - Exit 1 if any of these fail: 1920×1080; duration 55–65; h264 and aac; I in −19..−17; TP ≤ −1.0;
       LIMIT ≤ 6.
  6. Sheet: one frame at each of 0.5, 7, 12.5, 17.5, 21, 25, 28, 31, 34.5, 37.5, 40.5, 44, 48, 49.8, 52.5, 55,
     59 and 61 s. Use `select` on those times, `scale=480:-1`, and `tile=6x3`, into `sheet.png`.
  7. Only after all of that passes, `rm -rf builds/trailer/raw`.
